# FeatureModules — hệ tính năng dạng module

Mục tiêu: thêm một tính năng meta (daily gift, daily reward, win streak…) chỉ bằng package của nó và một asset module, không sửa `ProfileManager`, `PlayerData` hay `SaveService`. **Xóa folder package của một tính năng thì project vẫn compile sạch** — đây là tiêu chí bắt buộc cho mọi tính năng module.

Trạng thái (2026-11-20, nhánh `feature/feature-modules`): khung đã xong; đã chuyển **DailyGift**, **DailyReward**, **UserProfile**, **Heart**, **LavaQuest**, **RecordTracking**. WinStreak, MissionControl, TowerRise và CardCollection đã tạm gỡ; Đã xóa `GameFeatureContext`, `ContextData` và các interface inject cũ; `FeatureRegistry` là hệ quản lý feature duy nhất. Đây là game mới nên **không có chuyển đổi save cũ**.

## Thành phần
| File (`Assets/...`) | Trách nhiệm |
| --- | --- |
| `Packages/FeatureModules/Runtime/IFeature.cs` | Hợp đồng chung: `Id`, `Initialize()`, `IsEnabledFeature()`, `ToJson()` |
| `Packages/FeatureModules/Runtime/IFeatureLevelResult.cs` | Hook tùy chọn: `OnLevelWin(resultId)`, `OnLevelLose(resultId)`; gọi qua `Features.OnLevelWin/OnLevelLose` |
| `Packages/FeatureModules/Runtime/FeatureManager.cs` | Lớp cơ sở `FeatureManager<TData, TConfig>`: giữ `Data`, `Config`, `Services`; `Bind` (internal), `OnInit()`, `Save()` |
| `Packages/FeatureModules/Runtime/FeatureModule.cs` | Asset `FeatureModule` (giữ `id`) và `FeatureModule<TFeature, TData, TConfig>` (giữ `config`, tạo feature) |
| `Packages/FeatureModules/Runtime/FeatureRegistry.cs` | Danh sách asset module trên `ProfileManager`, tạo feature, `Get<T>()`, chuyển tiếp hook `Update` / `OnNewDay` / `OnTrackingOpenApp` |
| `Packages/FeatureModules/Runtime/FeatureServices.cs` | Dịch vụ inject một lần: `Save`, `Player`, `Time`, `RemoteConfig` |
| `Packages/FeatureModules/Runtime/FeatureSaveEntry.cs` | Một entry lưu `{id, json}` |
| `Packages/FeatureModules/Editor/FeatureModuleCollector.cs` | Menu **FoodPop/Feature Modules/Collect Modules**: gom mọi asset `FeatureModule` vào `ProfileManager` của scene đang mở, bỏ ô trống; cũng chạy khi import asset module |

Các hook `IFeatureUpdate`, `IFeatureNewDay`, `IFeatureTrackOpen` nằm riêng trong `FeatureModules/Runtime`, không còn phụ thuộc ContextData. `IFeatureLevelResult` thêm khi chuyển LavaQuest; đã gỡ các hook cảnh báo thua và UI Home tự chạy.

## Điều kiện mở tính năng
- Mọi feature triển khai `IsEnabledFeature()` qua `IFeature`; `FeatureManager` khai báo abstract để feature mới bắt buộc có điều kiện mở.
- DailyGift, DailyReward, Heart, UserProfile và RecordTracking dùng `Config.isFeatureEnabled`, mặc định true trong code và asset. Đã bỏ LevelActiveFeature khỏi năm config này; bật/tắt không phụ thuộc level người chơi. Chỉ LavaQuest giữ LevelActiveFeature mặc định 1 và UnlockLevel từ remote hoặc config.
- LavaQuest có `UnlockLevel`: ưu tiên `Services.RemoteConfig.level_unlock_busquest` khi có RemoteConfig, nếu không dùng `Config.LevelActiveFeature` (mặc định 1). `IsEnabledFeature()` chỉ kiểm tra level người chơi; đã gỡ cờ config isFeatureEnabled và các property IsEnabled, isActive, IsLevelUnlocked. Runtime và UI dùng chung IsEnabledFeature, UI khóa vẫn hiển thị UnlockLevel.
- Đây là API truy vấn cho Home/UI/gameplay chủ động sử dụng; registry vẫn nạp/lưu và chuyển hook ngày mới cho mọi module, không tự mở popup hoặc tự bỏ qua hook khi đổi cờ/điều kiện.

## Luồng chạy
1. `ProfileManager.InitializeProfile` → `SaveService.Load()` → tạo `FeatureServices` → `featureRegistry.InitializeFeatures(services)`.
2. Với từng asset trong `Modules` (theo thứ tự danh sách): ô trống (asset đã bị xóa) → `Debug.LogWarning` và bỏ qua; `id` trống hoặc trùng → `Debug.LogError` và bỏ qua; module hợp lệ chạy `CreateFeature` → `SaveService.LoadFeature<TData>(id)` → `feature.Bind(...)` → `SaveService.RegisterFeature(feature)` → phân loại hook. Sau khi **mọi** feature đã đăng ký, cache `IRecordTracking` tùy chọn vào dịch vụ người chơi core rồi mới gọi `Initialize()` → `OnInit()`, nên `OnInit` được phép gọi `Save()` hoặc `Get<T>()` feature khác.
3. Sau khi mọi module và callback ngày mới đã đăng ký, `InternetConnection` xác thực giờ rồi gọi `TimeManager.Synchronize()`: đồng hồ tự kiểm tra ngày và phát callback trước khi kết nối báo sẵn sàng. `ProfileManager.Start` chỉ đợi xác thực (hoặc cheat), cập nhật bù thời gian cho feature → xử lý phiên chơi → ghi tracking mở app → lưu hồ sơ và đồng hồ → bật `IsReady`. Quà lần mở đầu cộng qua `IHeart` trước lần lưu cuối khởi động. Lượt bị bỏ dở xóa `isPlaying`, trừ mạng, reset win streak qua `IRecordTracking` nhưng không tăng retry, rồi báo thua feature.
4. `FeatureRegistry.InitializeFeatures()` tạo/đăng ký toàn bộ module trước khi Initialize, `RegisterFeature()` là helper phân loại hook. `FeatureRegistry.UpdateFeatures()` gọi `OnUpdate()` của mọi `IFeatureUpdate`: chạy một lần trong Start sau xác thực giờ để bù thời gian trước xử lý phiên chơi, rồi được `ProfileManager.Update` gọi mỗi frame sau `TimeManager.CheckForNewDay()` khi `IsReady`. `OnNewDay` reset core, chạy mọi hook qua registry rồi chủ động lưu toàn bộ hồ sơ trước khi TimeManager lưu mốc ngày; không phụ thuộc module thống kê/sự kiện để lưu hộ. Hook ngày mới của RecordTracking/LavaQuest không tự lưu. `FeatureRegistry.TrackAppOpen()` chuyển tiếp hook `IFeatureTrackOpen.OnTrackingOpenApp` một lần trong Start sau xử lý phiên chơi; chỉ đổi dữ liệu, lần lưu cuối khởi động ghi nhận thay đổi đó.
5. Home tự quản lý quyết định mở popup. Đã gỡ `IFeatureHomeSuggest`, danh sách HomeSuggests, CheckSuggest/IsSuggestOpen và cờ isSuggested của DailyGift/DailyReward; không tự gợi ý hai popup khi vào Home. Giữ popup và nút mở thủ công. Đã gỡ IFeatureHomeFlow, HomeFlows, RunHomeFlow và các cờ popup kết quả chờ của LavaQuest; Home không tự chạy popup kết quả khi quay về. Đã gỡ IHomeTutorial, CheckShowTutLiveOps và tutorial tự chạy trên nút LavaQuest; chỉ giữ luồng IAP hiện có.
6. UI của chính package lấy feature qua `XxxFeature.Instance` (= `ProfileManager.instance.Features.Get<XxxFeature>()`). Code ngoài package **không** được tham chiếu kiểu của package; nếu cần thì thêm interface hook trong `FeatureModules`.

## Lưu dữ liệu
- Lưu chung một key `PLAYER_DATA`. `PlayerData.features` là `List<FeatureSaveEntry>`, mỗi module một entry theo `id`; chưa có entry thì feature bắt đầu từ `new TData()`.
- `SaveService.SaveData()` ghi `ToJson()` của mọi feature đã đăng ký vào entry rồi lưu một lần, nên coin và trạng thái feature luôn được ghi cùng nhau.
- `FeatureManager.Save()` chỉ gọi `SaveService.SaveData()`; không lưu TimeManager như `ProfileManager.SaveData()`.
- **Entry không đọc được** (JSON rỗng hoặc sai): `Debug.LogError`, entry được đổi tên thành `<id>.unreadable` để giữ JSON gốc cho việc khôi phục tay; feature chạy lại từ model mới và tiến trình mới được lưu bình thường dưới `id`.
- Xóa package: entry của nó vẫn nằm trong save; thêm package lại thì tiến trình quay về.
- **Xem/sửa dữ liệu khi Play:** Inspector `ProfileManager` → `Feature Registry` → `Registered (Play mode)`: mỗi phần tử đặt tên theo `Id` (ví dụ `daily_gift`); mở ra thấy `Id`, `Data` (Odin `[ShowInInspector]` trên `FeatureManager.Data`, giá trị trực tiếp, sửa tay được) và nút **Lưu dữ liệu** (ghi ngay xuống `PLAYER_DATA`). `Player Data` → `Features` → `json` chỉ là bản đã ghi ở lần lưu gần nhất. Ngoài Play mode không có feature nào chạy nên không sửa được ở đây.
- **`id` của module là khóa lưu: không trống, không trùng, không đổi sau khi phát hành.**

## Đồng hồ và Internet bắt buộc (`TimeManager`, `Services.Time`)
- Mọi tính năng lấy giờ qua `Services.Time.GetNow()`. TimeManager giữ đồng hồ và sự kiện ngày; `Common/Network/InternetConnection.cs` xác thực Internet bằng HTTPS HEAD tới Google `/generate_204` và header `Date` (timeout 3 giây). Thất bại không thay bằng giờ máy.
- `ProfileManager.Awake` nạp model và đăng ký module theo mốc giờ đã lưu; chưa có mốc thì dùng mốc tạm 1970, không lấy ngày máy. `Synchronize()` tự kiểm tra ngày ngay khi nhận giờ online (trừ cheat), trước khi InternetConnection mở chặn; `Start` chờ xác thực hoặc cheat trước khi xử lý phiên chơi và cho phép luồng Home/gameplay. Update của feature bị chặn khi kết nối chưa hợp lệ.
- Giờ thật = UTC máy chủ đã xác nhận + `Time.realtimeSinceStartupAsDouble` đã trôi; không phụ thuộc chỉnh ngày/giờ máy hoặc `Time.timeScale`. Khi dừng vì mất mạng, đồng hồ vẫn tiến; feature cập nhật khi được chơi tiếp.
- **Ngày thưởng theo local cố định:** lần xác thực online đầu tiên chọn offset múi giờ thiết bị và lưu cùng `lastRewardDate`. Giữ nguyên offset qua ngày mới, đồng bộ online và mở lại app; không nhận thay đổi múi giờ/DST của thiết bị. Save đã có offset tiếp tục dùng giá trị đó. Chỉ chọn lại khi xóa dữ liệu và khởi tạo đồng hồ mới. Chỉ mở ngày mới khi ngày local xác thực lớn hơn ngày thưởng đã lưu; ngày bằng hoặc lùi không reset. Không còn lưu `nextDayUtcTicks` vì offset đã cố định. Mọi feature tiếp tục dùng `GetNow()` theo local cố định nên hạn hồi mạng, mạng vô hạn và cooldown không bị nhảy do đổi múi giờ. `cheatTime` vẫn dùng giờ máy để test.
- Rút gọn TimeManager: so sánh ngày local với `rewardDate` cache trong RAM; chỉ định dạng `lastRewardDate` khi thật sự đổi ngày. Đã bỏ biến hạn nửa đêm UTC và các helper tính mốc ngày riêng; GetNow tính trực tiếp UTC đã xác nhận + realtime + offset cố định. Save cũ tiếp tục đọc ngày thưởng và offset đã lưu. Kiểm chứng: 31 kiểm tra clock và 12 kiểm tra kết nối PASS với code thật/engine-HTTP-storage giả lập, gồm mở lại qua ngày mới, giờ lùi, offset cố định và cheat; `git diff --check` qua. Chưa kiểm thử Play Mode hoặc thiết bị thật cho phần rút gọn này.
- TimeManager tự kiểm tra ngày trong `Synchronize()` ngay sau mỗi lần xác thực UTC, không còn API kiểm tra đăng nhập riêng hoặc lời gọi kiểm tra ngày từ ProfileManager. `CheckForNewDay()` tiếp tục phát hiện qua nửa đêm khi chơi; lần cập nhật cheat đầu tiên tự đặt mốc test, không phát ngày mới chỉ vì bật cheat.

## Cấu trúc thư mục
```
Assets/Packages/
  FeatureModules/          khung dùng chung
    Runtime/               IFeature, FeatureManager, FeatureModule, FeatureRegistry, FeatureServices, FeatureSaveEntry
    Editor/                FeatureModuleCollector
  <Feature>/               ví dụ DailyGift
    Runtime/               <Feature>Feature, <Feature>Data, <Feature>Module, class config
    UI/                    script UI (MonoBehaviour)
    Configs/               asset config + <Feature>Module.asset; asset con trong thư mục con (Configs/Rewards/)
    Prefabs/UI/            prefab UI
    Prefabs/Resources/     chỉ prefab thực sự nạp bằng Resources.Load; popup UIRef đặt ở Prefabs/
    Editor/                tool editor riêng (nếu có)
    Legacy/                code cũ, chỉ giữ tới khi kiểm chứng xong
```

## Mẫu chuyển một feature (theo DailyGift)
1. `XxxManager : ContextData<XxxData>` → `XxxFeature : FeatureManager<XxxData, XxxConfig>` + interface hook cần dùng. Giữ nguyên logic nghiệp vụ; feature override `IsEnabledFeature()` theo config phù hợp: isFeatureEnabled mặc định true cho tính năng bật/tắt; UnlockLevel cho tính năng mở theo level như LavaQuest.
2. `ProfileManager.instance.PlayerDataManager` / `TimeManager` → `Services.Player` / `Services.Time`; `ProfileManager.instance.SaveData()` → `Save()`; field config → `Config`.
3. Thêm `public static XxxFeature Instance => ProfileManager.instance.Features.Get<XxxFeature>();`.
4. Tạo `XxxModule : FeatureModule<XxxFeature, XxxData, XxxConfig>` (có `[CreateAssetMenu]`, thân rỗng). Đặt file theo mục "Cấu trúc thư mục"; manager cũ chuyển vào `Legacy/`.
5. Tạo asset `XxxModule` trong `Packages/<Feature>/Configs`, đặt `id` (snake_case) và gán config; chạy **Collect Modules** rồi lưu các scene có `ProfileManager` (`Load.unity`, `HotPotDemo.unity`).
6. UI trong package: thay `ProfileManager.instance.GameFeatureContext.XxxManager` bằng `XxxFeature.Instance`.
7. Khi khôi phục feature cũ, bỏ mọi phụ thuộc vào GameFeatureContext/ContextData (hai lớp đã xóa), không thêm manager/model vào core. Code ngoài package dùng interface trong FeatureModules; UI chung dùng hook, dịch vụ dùng FeatureServices.
8. **Kiểm tra xóa folder:** tạm chuyển `Packages/<Feature>` (kèm `.meta`) ra ngoài `Assets`, refresh Unity → không lỗi compile; trả về chỗ cũ, refresh, chạy Collect Modules nếu scene đang mở mất tham chiếu.
9. Bổ sung comment EN/VI, sắp thứ tự thành viên theo AGENTS.md, cập nhật tài liệu này.
